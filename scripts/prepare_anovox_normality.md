# AnoVox Normality数据集分析

## 当前下载的数据集

**数据集**: AnoVox_Normality_Mono_Town03
**大小**: 7.1 GB
**内容**: 仅包含LiDAR点云数据（.npy格式）

```

└── Scenario_486bab15-e643-418f-9c8b-4a1e8a954f6f/
    └── LIDAR(0, 0, 1.8)(0, 0, 0)_6343367489698313030/
        └── *.npy (点云文件，形状: Nx4, 包含xyz和intensity)
```

## 问题分析

### ❌ 缺少的数据

1. **图像数据**：代码期望 `train/images/` 和 `test/images/` 目录
2. **异常掩码**：代码期望 `train/anomaly_masks/` 和 `test/anomaly_masks/` 目录
3. **相机标定**：代码期望 `train/calibrations/` 和 `test/calibrations/` 目录
4. **训练/测试分割**：没有明确的train/test目录结构

### ⚠️ 数据格式不匹配

- **点云格式**：代码期望 `.bin` 格式，但数据集是 `.npy` 格式
- **目录结构**：代码期望标准的train/test结构，但数据集是按Scenario组织的

## 解决方案

### 方案1：寻找包含完整数据的版本（推荐）

在Zenodo上查找包含以下内容的版本：
- 图像（RGB相机）
- 点云（LiDAR）
- 异常掩码（Ground Truth）
- 相机标定（内参+外参）
- 训练/测试分割

### 方案2：适配当前数据集格式

如果必须使用当前数据集，需要：

1. **修改数据集加载器** (`src/data/anovox_dataset.py`)：
   - 支持 `.npy` 格式的点云
   - 适配Scenario目录结构
   - 处理缺少图像和掩码的情况

2. **创建占位符数据**：
   - 如果没有图像，创建空白图像
   - 如果没有异常掩码，创建全零掩码（所有样本都是正常样本）
   - 如果没有相机标定，使用默认值

3. **注意**：
   - 如果只有"Normality"（常态）数据，无法进行异常检测训练
   - 需要找到包含异常样本的数据集

### 方案3：使用其他数据集

如果AnoVox数据集不完整，可以考虑：
- 使用nuScenes数据集（但需要异常标注）
- 使用其他异常检测数据集（如Road Anomaly, Fishyscapes等）

## 下一步建议

1. **检查Zenodo上的其他版本**：
   ```bash
   ./scripts/check_anovox_versions.sh
   ```

2. **查找包含异常数据的版本**：
   - 查找标题中包含 "Anomaly"、"Abnormal" 或 "Dynamic" 的版本
   - 查看数据集描述，确认包含异常样本

3. **如果找到合适的版本**：
   - 下载完整数据集
   - 验证数据集结构
   - 运行验证脚本

4. **如果只有当前数据集**：
   - 需要修改代码以适配格式
   - 但无法进行异常检测训练（只有常态数据）
